# 需求编辑布局、图片交付与折叠筛选规格

本方案由用户逐项确认并明确开始实施。仅在原云端工程、现有功能分支与草稿 PR 开发验证；本轮无服务器部署授权。保留已交付项目改版、一次性码弹框、普通草稿与全部既有业务规则。

## 已确认体验

需求新建与编辑只调整内部布局，不更换现有容器：新建目前是主内容区的独立 dialog section，编辑为 Ant Design Vue Modal。顶部大标题、需求背景、截图区域；底部优先级、只读项目与创建者；另一张“补充细节”折叠卡包含细化说明、验收条目及验收人、来源、职责和期望完成时间。新建按钮“保存草稿”真实调用创建 API，保存服务器 draft；编辑为“保存修改”，仍发送原 refine 或 revise 命令。保留原表单标题与修订说明，不能让按钮文案掩盖业务差异。

背景复用现有“来源说明”字段，上方以背景区承载；来源链接等继续在补充细节中。不新增含义重复的背景字段。创建者新建时显示当前提交人；编辑从原创建事件读取不可变创建者，读取失败明确标识并可重试，不能把当前编辑人假称创建者。项目与创建者均只读。

期望完成时间为选填自由文本，例如“本周五前”“下个版本”；仅记录文字，不解析日期、不自动逾期、不新增提醒或工作计划。实现字段为 `expectedCompletion?: string`，上限 2,000 UTF-16 单位，沿用 narrative 文字/Unicode/控制字符校验，空字符串可清除，保留原空白与换行。该字段属于说明元数据，允许在原权限下的创建、refine 和 editorial/behavior revise 中修改；editorial 保持功能 revision，正常对象 version 与审计仍递增。不能借此绕过其他字段的 editorial 限制。

## 持久化与兼容性

现有 objects.current 与不可变范围/修订快照均存完整 JSON。新增可选属性不新增 SQL 列，不重写旧记录或历史快照，不为旧记录填充虚构时间。旧记录缺少字段时前端显示未填写；旧客户端未发送该字段时编辑保留原值。新增 API 字段只进入明确的创建/refine/revise 白名单。GET、列表、事件和范围快照保持真实值，Vue 文本渲染，不使用 v-html。

必须用旧形状数据库验证迁移幂等、读取、持久化重启及历史不变，并用基线版本验证回退读取/更新保留未知 JSON 属性。回退后的旧界面不提供新字段编辑，旧 API 不能接受新字段；完整回退须使用配套旧前后端，不能套用上一轮“API 完全未变”的结论。本轮是否需要 SQL 迁移以实现和实测为准；当前采用可选 JSON 扩展，无 DDL 迁移。

## 表单及草稿边界

保留标题/来源/细化说明等原必填条件、产品指定验收人权限、验收条目的稳定 ID、required 与 exclusionReason；折叠内容保持挂载参与校验，错误时展开并定位字段。refine 与 revise 的状态、revisionKind、reason、affectedTaskIds、affectedCheckIds、impactConfirmed 和版本冲突采用条件不变。Ctrl/Cmd+S 使用同一校验与提交入口，提交中不能重复操作。

普通文字自动暂存继续按成员和原表单键隔离。新建“清空”恢复空白初始值；编辑“清空未保存修改”恢复本次打开的原始值，保留验收 ID、服务端对象、版本与既有附件。均需明确确认，取消不清空、不提交。正在提交或保存结果未确认时不可清空形成新创建请求。

## 图片选择与分阶段交付

支持粘贴、拖入、点击选择和本地缩略预览；编辑可查看既有附件。沿用 PNG/JPEG/WebP、默认单张 5 MiB、最多 10 张/对象、20M 像素及服务端最终配额/格式/权限。文件和 Blob URL 仅在当前成员内存中存在，不进入 localStorage、普通草稿、日志或 URL。无效格式/过量/过大应明确反馈，不能静默丢失。移除待上传项和清空不删除已保存附件。

先成功保存对象，再按序上传图片，继续使用既有附件 API、expectedVersion、CSRF、会话与每项稳定的 Idempotency-Key。现附件成功不推进对象版本；外部对象变化仍可产生 409。每项保留原文件、绑定版本和键，以便丢响应后按原请求重试；成功项不能重复上传。明确版本冲突才允许用户核对并采用新版本后为相应未执行项换键，不能给未知结果请求随意换键。

创建请求发送前持久化安全的原始命令指纹和幂等键。结果未知时保留原命令并提供原请求重试，禁止修改/清空后再次创建造成重复。已确认保存后保留安全的对象 ID/版本回执，后续重试只处理失败图片，不再次创建或重复编辑对象。回执不含图片二进制。刷新后明确告知图片无法恢复，并提供已保存对象入口，不恢复空壳图片或假成功。已保存对象与图片状态分别呈现：全部成功才按完成导航；部分失败保留对象与失败项，提供重试和明确放弃未上传图片后查看对象。

关闭、取消、路由离开或刷新有未上传文件时明确提示丢失风险；上传中阻止离开和重复请求。成员变化/卸载/移除时释放文件引用及 Blob URL，迟到响应不得恢复另一成员或已关闭表单。普通文字草稿保护继续有效，不能宣传图片刷新可恢复。

## 筛选覆盖及交互

项目目录、项目工作列表（概览/需求/任务/Bug/测试验收中的列表条件）、我的工作主列表及工作更新选择列表、成员列表统一复用 `FilterPanel`。项目切换、责任页签、测试/验收队列、刷新操作、日报生成范围及侧栏导航搜索保持原用途，不当作列表条件一起隐藏。

每个列表默认仅显示“筛选”和生效条件数量。展开从已应用条件克隆临时值；输入/重置不请求、不改变列表。“确定”一次性应用全部条件、回第一页并收起；“重置”只将临时值置默认；“收起”或再次点击筛选按钮放弃临时修改，保留已应用条件。再展开重新取已应用值。跨成员/项目/队列等查询身份变化关闭未确认面板，迟到数据不得覆盖新范围。

项目目录关键词仍本地筛选已加载的完整项目目录；归档默认 all，活动/归档分区逻辑保留。我的工作主列表和成员关键词仍只筛选已加载记录，不偷偷增加后端搜索；工作更新选择器仍使用既有 my-progress 的 q。项目对象关键词仍使用原 `/api/search` 及原项目范围。明确提示本地关键词只作用于已加载记录。不能把列表分页计数改成全库总数。

项目对象/我的工作/成员的已应用条件在前端路由中表达，原有 q 保持项目对象搜索语义，其他新增前端参数不透传为未知 API 查询。应用条件一次路由变更，避免条件逐项变更造成中间请求；翻页只使用已应用条件。保留 workTab、queue、projectId、view、创建上下文与原路径/哈希的有效关系；普通标签切换依原行为清条件/保留搜索。全局项目范围不被显式项目路径覆盖。

顶栏不保留另一份关键词输入。原全局搜索入口改成只导航的按钮，进入既有全局范围的项目工作列表并展开同一个筛选面板，输入和确认均在该面板；不另存顶栏搜索值。全局范围继续取现有全局项目选择，区别于显式项目页；这项入口适配不新增搜索 API 或扩大搜索口径。

## 实现取舍与非目标

采用现有 JSON 对象的可选元数据扩展，而非新日期列/提醒系统；采用共用表单的局部分段和独立图片队列，而非重写所有动作表单；采用受控筛选草稿与路由原子应用，而非逐输入立即查询。上述均为实现选择，非另获用户业务授权。用户已确认最终结构并明确开始，因此不重复请求产品或部署确认；如出现实质新业务冲突再报告。

不修改验收独立性、授权、原子领取、版本/幂等/审计、严重 Bug 阻塞、豁免规则、日报事实口径、票据安全、trustProxy、待定业务议题、服务器或真实数据。原参考图经支持流程及一次本地重试未能下载；原像素未在本执行器查看，不伪称视觉一致。最终使用合成数据检查桌面和手机。

## 完成门槛

三项任务分别先 RED 后 GREEN；旧数据库/回退兼容、自由文字边界、XSS 安全渲染、修订与权限、附件部分成功/未知响应/版本冲突/取消清理、全部筛选调用点及路由迟到响应均有针对性证据。独立代码与规格审查发现须修复。最终单元/API、类型、构建、完整浏览器、15 打包门禁及精确 HEAD push/PR CI 成功；固定应用 SHA 的 Linux 候选经过审计、生产冒烟和上传后下载回校。保留草稿 PR，不合并或部署；交接明确 API/存储/升级与回退边界。
