# 新建需求：用户操作流程

1. 在侧栏进入“项目”，打开目标项目，再点击“新建需求”（概览和需求列表均保留入口）。弹框打开后，原项目页面保留在遮罩后。
2. 当前项目产品看到“返回 / 保存草稿 / 提交为可执行需求”。有相应创建权限的岗位负责人可以保存草稿，不能代产品确认可执行；管理员也必须明确拥有项目产品角色才有该业务权限。
3. 先填写标题、来源说明或来源链接至少一项，并核对优先级与职责范围。来源链接使用 HTTPS。期望完成时间选填，可以写“本周五前”“下个版本”，不自动产生提醒。
4. 可以点击选图、粘贴或拖入截图，先在弹框预览。支持静态 PNG/JPEG/WebP，单张最多5MiB、每个需求默认最多10张、最多20M像素；服务器仍会校验。图片保留在本次页面内存，刷新不能恢复未上传图片。

## 保存草稿

内容尚未齐全时，点击“保存草稿”。沿用原有最低必填和格式限制；不用先填完细化说明、验收条目、验收人或来源核对结果。

保存的是有编号的服务器需求，状态为“草稿”，不是只存当前浏览器。没有图片或图片全部上传成功后，弹框关闭并进入该需求详情。之后可继续细化，再由产品确认可执行。

## 提交为可执行需求

展开“补充细节”，填写细化说明，选择有效的项目产品验收人，添加至少一个“必需”验收条目；条目编号保持稳定，排除条目必须填写排除原因。验收人须独立于该需求实际开发/修复参与者。

主动选择来源核对结果：

- “已人工核对”：表示本人已核对来源，时间由服务器记录。
- “无法核对”：填写原因，沿用现有业务允许的说明方式。

不会默认选择“已核对”。修改实质内容或恢复普通临时输入后须重新选择；只有结果未知的原请求会锁定原选择供原样重试。

点击“提交为可执行需求”。权限和完整性均由服务器再次检查；全部通过后一次创建为“待开始”，不要求再去详情重复细化和确认。没有图片或图片全部上传成功后，进入需求详情；活动历史明确显示“创建并确认可执行”、提交产品和来源核对结果。需求仍需按原流程拆分执行任务，不直接领取需求。

## 失败、等待和返回

- 校验失败：弹框保留输入和图片，并显示错误；不会偷偷创建草稿。补齐后可重试，也可以主动选择保存草稿。
- 提交中：保存动作与关闭受保护；重复点击不会另建需求。
- 正式提交成功、图片失败：需求已经是“待开始”，其他成员可能已经开始处理。页面明确显示需求编号、保存结果、图片成功/失败数量；点击“重试失败图片”只补传失败项，不重新创建需求，也不撤回可执行状态。可选择“查看已保存需求”；放弃未上传图片会有确认。以详情读取到的当前业务状态为准。
- 草稿保存成功、图片失败：服务器草稿同样保留；页面说明本次保存为草稿，失败图片可单独重试。
- 请求结果未知：保留原请求，两个保存动作停止使用，仅提供“重试确认保存”。重试沿用原提交方式和幂等键；返回、重新打开或刷新不能改为另一次创建。重试遇到403仍不能据此判定原请求没成功，应核对原需求或恢复权限后重试。
- “返回”不提交业务数据。普通文字沿用当前账号浏览器自动防丢恢复；若暂存失败或有未上传图片，会明确提示可能丢失。不要把浏览器恢复内容当作已经保存的服务器草稿。
- “清空”只恢复当前未提交输入，不能删除服务器已保存需求和附件。
